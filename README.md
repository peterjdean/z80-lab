# Z80/LAB — v1.0.1

A browser-based Zilog Z80 development environment with a tested native C++
CPU core compiled to WebAssembly, an integrated ASM80 assembler, serial I/O,
source-aware debugging, breakpoints, register and memory inspection, and portable
saved sessions.

**Public application:** https://z80.peterjdean.com/
**User guide:** https://z80.peterjdean.com/help.html (also [in this repository](web/help.html))

## What it does

- Emulate a Z80 with 64 KiB of RAM, instructions/T-state counters and a
  configurable virtual clock (2, 4, 6, 8 MHz or unlimited).
- Assemble and load single-file Z80 programs entirely in the browser. View
  their machine-code listing, export Intel HEX, open/save assembly source.
- Run, pause, step an instruction or step to the next mapped source line.
  Set breakpoints from the source gutter, disassembly, or an address.
- Inspect/change registers, PC and memory; use virtual serial ports 00/01/02
  through the terminal; load bundled example programs or local HEX/TXT/BIN.
- Save and reopen a `.z80session` file containing CPU, RAM, workspace,
  debugger settings and terminal text. Sessions always reopen paused.

The application has **no login, database, cloud session storage, analytics
backend, or third-party runtime CDN**. Source and session files are processed
locally in the browser. Saving a session downloads a file onto your device.

## Browser compatibility and limitations

**Safari 16+ is the public release target**, because the enforced Content
Security Policy uses `wasm-unsafe-eval`. Current browsers supporting standard
WebAssembly and ES modules are expected to work, but were not all independently
verified. The browser build runs without pthreads, memory64 or SIMD.

The ASM80 assembler (MIT-licensed `@asm80/core` 1.3.0) is not Pasmo; source
code compatibility is not guaranteed. `INCLUDE` and `INCBIN` are deliberately
unsupported. Source stepping enters calls; it is not a step-over feature.
Source mapping is invalidated by modifications to the source or executable
memory and should be regenerated by assembling again. Full Z80 conformance
has not been established in the browser; the native core passed previous
ZEXDOC/ZEXALL tests on Euler (67/67).

## Build and test

Native tests on Ubuntu/Linux:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

WebAssembly build on Euler (with Emscripten already installed):

```sh
source ~/emsdk/emsdk_env.sh
bash scripts/build_euler_web.sh
```

GitHub Actions independently runs native, assembler, WebAssembly,
release-archive and deployment/rollback tests. Its `z80-lab-static-site`
artifact contains a SHA256-verified ZIP and checksum. Runtime assets include
`index.html`, `help.html`, `assembler.js`, `z80wasm.mjs`,
`z80wasm.wasm`, bundled examples, `LICENSE`, `THIRD_PARTY_LICENSES.txt`
and `EMSCRIPTEN_LICENSE.txt`.

## Deployment and release

The public HTTPS deployment on Popper uses a **separate document root**
(`/var/www/z80-lab-public/current`) from the localhost-only staging
installation (`/var/www/z80-lab/current`, port 8082). Releases are verified
and installed into versioned directories with atomic promotion and rollback;
GitHub CI does not deploy automatically or hold Popper credentials.

See [RELEASE.md](RELEASE.md) for the v1.0 promotion and tagging checklist.
Historical development notes are retained in [WEB.md](WEB.md),
[DEPLOYMENT.md](DEPLOYMENT.md) and [PUBLIC_DEPLOYMENT.md](PUBLIC_DEPLOYMENT.md).
